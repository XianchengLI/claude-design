
### Control tower (level 3)

- **Roles.** One resident *control tower* session (topic column says `control tower`) schedules, dispatches, collects reports, rules, and merges `<INBOX>`. It does **no content work** (long reading, code search, runs): that is what makes it grow. Worker sessions do one row each. The main ✓ in SESSIONS is only the CLAUDE.md write right, not the tower role.
- **Shifts.** The tower is a post; sessions rotate through it. Hand over with `/tower-out` (writes the baton `<HANDOVER>`, overwritten each shift), take over with `/tower-in`. Measure context with `python <KIT>/ctx_usage.py <own 8-char id>`, never self-estimate: above <SOFT>k stop dispatching and hand over at the next quiet point; <HARD>k is a hard handover.
- **Dispatch.** At most <MAXW> workers in flight, at most <MAXH> heavy (holding the harness / long runs). The tower confirms start cards itself and forwards to the user only those > 1 h, needing bulk Claude judging, or contending for an exclusive resource. With cross-session messaging (ListAgents / SendMessage), the tower sends the card to the new window and workers send close-out reports to the tower's agent name; otherwise the user copies them.
- **Rulings.** The tower rules on anything it can justify and logs it in `<TOWERLOG>` (`date time · recv|send|rule|ask · what · why · where`, append only, time from the local `date`). The user is asked only for: (1) outward and irreversible actions, (2) product-behaviour or external-number changes, (3) data-rule boundaries, (4) conflicts with an earlier user ruling, (5) > 2 h wall-clock or work only the user can do. When asking, give the whole picture: where things stand / what this blocks / options and costs / recommendation / what happens by default if unanswered.
- **Questions to the user** go only in a final block `## ❓ Open questions (N)`, numbered, one question per line, nothing after it.
- **Rules from worker sessions** go to `<INBOX>` as `date · session · target section · rule · why`; only the tower merges them (anchor-delete merged entries, never overwrite the file).
