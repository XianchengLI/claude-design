# /tower-in — 控制塔接班

上位规则：`.claude/tower-rules.md` 的 Control tower 节。路径取自 `tower.json`。**恢复岗位靠文件，不靠继承对话**，所以本 skill 的动作全是读文件。

## 1. 确认主权

读 `sessions` 表：
- 没有别的活着的 session 主题写着 `control tower` → 本 session 接班。
- 另一个控制塔还活着 → 停下问用户：接管，还是让对方继续。不要自己抢。
- 主 ✓ 在某个干活 session 手上 → 告诉用户要把 ✓ 移回控制塔，得到同意后再改表。

本行填上：主题 `control tower · agent <ListAgents 输出里自己的名字>`（没有跨 session 消息功能就省掉后半），分支填「无」，独占留空（控制塔只改共享文件，只按锚点追加）。

## 2. 按顺序读（不要并行读一堆再拼）

1. `handover`：重点看「悬而未决」和「下一班第一件事」，这两段别处没有。
2. `memory`：各线状态。
3. `tasks`：先看进行中和 Ready to start。
4. `inbox`：非空就现在合并进 CLAUDE.md，然后只按锚点删已合并的条目。
5. 跑 `python ~/Documents/claude-design/scripts/tower/ctx_usage.py <自己前 8 位>`，记下实测上下文。

## 3. 核对在跑的 session

对照 `sessions` 表和进行中：已收工但清单行没动的，去它的落点确认结果，再移行；闲置超过 2 h 的，提醒用户它可能断了；接力棒说在等的回报，去落点看是否已写好。

## 3b. 过一遍排队全表，清掉过时行

先看接力棒里「本班让哪些行过时」那一段，再逐行问四个问题：前置条件还成立吗？还该做吗（是否被否掉或被别的行吸收）？启动卡里的基线和前提还对吗？编号和引用对吗？
**Queue 很长时**（通读要花上万 token），派一个只读子 agent（不降档）按这四问过全表，只带回「哪几行过时 + 为什么 + 建议怎么改」，控制塔核过再改。只改清单行和卡，不开新活。

## 4. 报现状，然后停下

不复述文件内容，只给判断：
1. 上一班留了什么（一句）+ 悬而未决剩几条；
2. 现在在跑什么，各在等什么；
3. 建议第一件事。点到的每一行都必须已有启动卡，没有就先写卡，写不了只报卡点；
4. 全表过时行的一行汇总（过了 N 行，改了 M 行）；
5. 要用户拍板的，放在最末的 `## ❓ Open questions (N)` 块。

然后停下等用户。控制塔的第一件事是对齐，不是干活。

## 红线

- 不继承对话：某个判断的理由在文件里找不到，就问用户，补完后写进正本。
- 不抢主权。
- 控制塔不亲自干内容活（长文档、代码搜索、跑批），这类活派出去。
